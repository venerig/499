Web server, application server, middleware: chi fa cosa nello stack

Lezione 37 — ripasso mirato: i tre livelli che spesso si usano come sinonimi sul lavoro, ma che il quiz vuole distinti.

Percorso: MISSION → Zona 🟢 → Application server e middleware (materia 9) → Lezione 1/… · Punteggio quiz: 0 / 0

Web server vs application server

Cosa serveEsempi
Web serverContenuto statico e richieste HTTP/HTTPS di base (file, reverse proxy)Apache HTTP Server, Nginx
Application serverEsegue la logica applicativa (business logic), genera contenuto dinamicoTomcat, WildFly/JBoss, WebLogic, IIS (con ASP.NET)

Il tranello più comune

Non sono sempre due prodotti separati: molti application server includono anche le funzioni di web server (es. Tomcat serve sia richieste statiche che esegue servlet/JSP). Il quiz distingue le funzioni (servire file vs eseguire logica), non necessariamente due software diversi installati fianco a fianco.

Architettura a livelli (3-tier / n-tier)

Schema classico: client (presentazione) → application server (logica di business) → database (persistenza). Il web server, quando presente come livello separato, si colloca davanti all'application server come reverse proxy/load balancer.

Middleware

Software che fa da ponte tra applicazioni o sistemi diversi, nascondendo la complessità dell'integrazione. Categorie tipiche da manuale:

TipoFunzioneEsempi
Message brokerScambio asincrono di messaggi tra sistemiRabbitMQ, Apache Kafka
ESB (Enterprise Service Bus)Instrada ed eventualmente trasforma messaggi tra molti sistemi enterpriseMuleSoft, IBM Integration Bus
Middleware dati (ORM)Fa da ponte tra codice applicativo orientato agli oggetti e database relazionaleHibernate, Entity Framework

Analogia per fissarla

Pensa al middleware come al layer di integrazione che già conosci tra microservizi: un message broker tipo Kafka tra due servizi è concettualmente lo stesso ruolo di "ponte" che un ESB gioca tra sistemi legacy enterprise — stessa funzione, scala e contesto diversi.

Verifica — retrieval practice

L'ordine delle opzioni cambia a ogni caricamento — rispondi dal ragionamento, non dalla posizione.

1. Qual è la differenza principale tra un web server e un application server?

Il web server gestisce richieste HTTP e contenuto statico; l'application server esegue la logica di business e genera contenuto dinamico. Alcuni prodotti (es. Tomcat) coprono entrambe le funzioni.

2. Quale di questi è un esempio di message broker?

Apache Kafka (e RabbitMQ) sono message broker: gestiscono lo scambio asincrono di messaggi tra sistemi. Nginx è un web server, PostgreSQL un database, NTFS un file system.

3. In un'architettura a 3 livelli (3-tier) classica, dove si colloca la logica di business?

Lo schema client → application server → database colloca la logica di business nel livello intermedio, separata dalla presentazione (client) e dalla persistenza (database).

4. Qual è la funzione principale di un middleware di tipo ORM (es. Hibernate)?

Un ORM (Object-Relational Mapping) traduce tra il modello a oggetti del codice applicativo e il modello relazionale del database, fungendo da middleware tra i due mondi.

5. Perché un prodotto come Tomcat può essere citato sia come web server che come application server?

Tomcat è un servlet container: serve contenuto HTTP e, al tempo stesso, esegue la logica applicativa Java (servlet/JSP) — da qui l'ambiguità nella classificazione che il quiz chiede di sciogliere.
